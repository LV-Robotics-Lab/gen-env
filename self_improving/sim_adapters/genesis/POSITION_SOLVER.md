# 已有场景图的位置求解与 Genesis 物理验证

现有 `validate_imported_scene` 入口默认执行：

**校验已有场景图 → 位置求解 → 干预式稳定化 → 独立基线与半时间步验收**

`reconstruct_media` 的物理阶段调用同一内部流程，随后沿用已验证终态渲染。
没有新增场景布置 CLI，没有新增模型解析或资产选择，也不自动改质量、摩擦、
碰撞体或替换桌面。旧自动换桌面、抬升和调摩擦的媒体修复分支已移出默认流程。

## 使用现有入口

在仓库根目录执行，输出目录与输入场景包必须分离：

```bash
venv/genesis/bin/python -m self_improving.sim_adapters.genesis.validate_imported_scene \
  --scene-package output/场景图物理_mouse_001/02_scene \
  --output-dir data/media_acceptance/my_graph_physics

# 相同输入恢复；已完整且匹配的阶段会复用
venv/genesis/bin/python -m self_improving.sim_adapters.genesis.validate_imported_scene \
  --scene-package output/场景图物理_mouse_001/02_scene \
  --output-dir data/media_acceptance/my_graph_physics --resume
```

首次输出目录必须不存在。默认完整流程要求两次回放均通过；顶层报告为
`workflow_report.json`。显式指定旧参数 `--profile baseline` 或 `--profile half_dt`
仍只执行一次自由回放，供独立诊断和兼容已有调用，不代表完整流程通过。

已有显式碰撞精度配置可通过 `--support-sdf-cell-size 0.0015
--support-sdf-max-res 384` 指定；也可来自场景清单绑定的 `support_sdf`，或已有
`derivation.json` 中的同名记录。它只作用于固定支撑，不会自动修补碰撞网格。
参数及实际加载距离场尺寸分别记录在物理输入和 `loaded_scene.json`。

直接物理 CLI 输出验证证据；四阶段媒体任务仍由 `reconstruct_media` 管理最终渲染。
其他调用者使用内部工作流结果和既有 `import_simfoundry_scene.preview` 完成展示，
必须先校验完整工作流已通过，不得只拿稳定化状态或单次回放结果开渲染门。

## 输入契约与位置求解

输入是现有导入格式的自包含场景包，包括场景图、布局、标准 URDF 资产及哈希清单。
图中的关系必须与布局一致，不从自然语言重新推断，也不添加无限地面。

- 1–12 个刚体、至少一个固定根及一个动态物体；每个动态物体有唯一 `on` 父节点，
  支撑链最终到达固定根。循环、缺失目标、固定物体被声明为支撑子节点会拒绝。
- 支持 `on`、`left_of`、`right_of`、`in_front_of`、`behind`、`near`、`far_from`。
  方位使用世界 +X 为右、−Y 为前；方向间隔 60 mm，near ≤180 mm、far ≥300 mm，
  距离使用包围盒 XY 间距。矛盾关系拒绝。
- 支撑区域须为带来源的目标局部水平凸区域，可在同一目标上有多个 `surface_id`。
  不接受用外包矩形填平孔洞或凹面；缺少合格区域时停止。
- 保留全部原朝向和固定根位姿；以原位置为起点，完整视觉及碰撞顶点投影到
  目标局部坐标，求取容纳完整足迹的区域，再进行有界搜索和回溯。
- 物理流程使用 20 mm 支撑边距、1 mm 释放间隙；每物体最大平移 0.5 m，
  每次放置最多 96 个候选，全场景最多 4096 条尝试记录。
- 非父子物体使用世界 AABB 保守排斥，可能拒绝几何可行的紧密摆放。结果是
  搜索顺序下首个可行候选，不宣称全局最优或真实碰撞已验证。

`position_solver.solve` 和原有独立提议入口仍可使用，版本为 v2；独立调用默认边距
仍为 10 mm，物理流程显式提升到 20 mm。它输出 `proposal_ready`、
`physics_status=not_run`，记录配置、输入哈希、候选拒绝原因和每项位移。
不支持容器内部、斜面、关节运动或自动旋转摆正。

## 稳定化与自由验收

干预式稳定化同时加载全部动态物体，固定根保持固定。每步推进后采集速度、位姿及
接触，再清零动态物体全部自由度速度；轨迹记录清零前的速度和 `zeroed_after_sample`。
不使用临时固定前景约束，不凭被清零后的速度宣称稳定。

稳定化配置：dt=0.004 秒、最多 2000 步；连续 50 步全部动态物体位置变化
≤0.1 mm、朝向变化 ≤0.001 rad，才检查候选是否可用。相对位置提议的位移超过
20 mm、转角超过 5°，或发生超过 1 mm 的穿透时停止。超预算明确失败；收敛后
重新检查支撑覆盖、方位关系和支撑面倾角。稳定化报告最多为 `candidate_ready`。

两个全新 Genesis 场景从同一稳定化候选、零初始速度开始独立自由回放：

| 检查 | 门槛 |
|---|---|
| 时长 | baseline 1000×0.004 秒；half_dt 2000×0.002 秒，均为 4 秒 |
| 末段 0.5 秒位移／转角 | ≤1 mm／≤0.5° |
| 末段最大线速度／角速度 | ≤0.01 m/s／≤0.05 rad/s |
| 全程穿透 | ≤1 mm |
| 每条声明支撑的末段向上接触比例 | ≥80%，并有实际力传递链通向固定根 |
| 全程目标局部完整足迹 | 边距 ≥20 mm，支撑面倾角 ≤0.5° |
| 方位关系 | 初态及末段均成立 |

自由回放不再清零速度，关闭休眠，动态前景不得被固定。非声明接触不能替代目标
支撑，非固定物体之间以及动态物体与非目标支撑之间的未声明接触会判为失败。
几何覆盖用完整视觉及碰撞顶点的凸包进行计算，不只检查物体中心。

## 产物、恢复与验证

四阶段任务保留 `01_obj`、`02_scene` 的已有资产与输入场景，派生场景在
`03_physics/workflow` 内：

- `position/`：完整求解输入、位置提议及新场景包。
- `stabilization/`：干预轨迹、加载审计、候选终态及派生场景包。
- `baseline/`、`half_dt/`：独立自由回放、完整轨迹、诊断视频、物理报告。
- `workflow_input.json`、各阶段 checkpoint、`workflow_report.json`：来源、
  代码/仿真版本、有效参数、哈希绑定及分阶段状态。

仅完整且配置/输入/依赖匹配的阶段复用。损坏或失配的阶段先归档，再重新运行；
SDF 改变保留位置阶段、重跑稳定化和自由验收；半时间步中断保留前序已完成阶段。
源资产变化失效其下游。物理代码变化不直接使媒体模型重建缓存失效。

`scene_physics_workflow.verify` 校验阶段文件集合、依赖链、稳定化收敛，并重算
两次自由轨迹。媒体最终渲染绑定完整工作流及半时间步结果，渲染失败只重试渲染。
`04_final_render` 使用验证终态独立生成视图和环绕视频，不复制诊断图片。

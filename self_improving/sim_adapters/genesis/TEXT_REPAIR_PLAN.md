## 运行

正式完整场景要求种子 **0、42、87** 各构建一次，每次通过后再执行对应半步复验，
共六次。三次构建必须使用同一份原任务绑定和合格资产；半步复验必须使用各自通过
尝试的原始释放初态。以下是完成资产资格与六次验收的命令，
不是已经取得完整场景通过的声明。

先以种子 0 构建；另两次将 `--seed` 和新输出目录分别替换为 42、87：

```bash
.venv/bin/python -m self_improving.sim_adapters.genesis.construct_asset_scene \
  --source-task 'output/桌上放着一个苹果、一个黄色杯子和一个橙色塑料碗。' \
  --output-dir data/genesis_text_repair/new_v2_seed_0 \
  --clip-index assets/genesis/clip_non_robot_v1/index.json \
  --fixed-object table_1 --seed 0 --profile text_repair_v1 \
  --repair-preset text_scene_v2 \
  --numerics-profile dt2ms_tau20ms_authored_v1 --render
```

仅当对应构建已封存为 `physics_passed` 后，运行半步工具；42、87 也分别使用自己
通过的源任务及独立输出目录：

```bash
.venv/bin/python -m self_improving.sim_adapters.genesis.replay_text_half_dt \
  --source-task data/genesis_text_repair/new_v2_seed_0 \
  --output-dir data/genesis_text_repair/new_v2_seed_0_half_dt --render
```

半步工具先校验源任务清单，独立复判最后通过尝试的 `physics_input.json` 与轨迹，
复制保留 `01_obj`/`02_scene` 后重新开始 `03_physics`。仅替换登记的数值配置及由
步长推导的采样数；资产、质量、位姿、关系、随机种子和 `repair_preset` 保持不变。
释放状态读取原 `physics_input.json`，禁止使用终态或启动修复循环重新采样。
`03_physics/source_baseline` 保留原输入、轨迹、判定与尝试/任务清单及哈希。
基线未通过、源清单变化或半步失败都不能进入 04；半步也必须独立满足完整 ≥95% 规则。

旧命令省略两个新开关时仍使用 legacy 修复及数值配置。为读取历史证据保留
`--profile text_repair_gt75_v1`：只将终末
稳定速度达标比例和预期父对象支撑比例改为 **严格大于 75%**。500 个终末采样至少
需要 376 个达标，375 个（恰好 75%）仍失败。其余物理、几何、资产准备和完整性
门槛不变。原 `text_repair_v1` 仍要求两项均 ≥95%，旧原生 baseline/half_dt 不变。
每次输入冻结所选配置，旧失败证据不会被新判据覆盖。v2 拒绝将这个历史 >75% 配置
用作正式验收。

输出目录必须不存在。`--fixed-object` 可重复，地面天然固定；中间承载物仍动态。
不传 `--render` 时，物理通过也不会运行 `04_final_render`。验证回放视频归属 `03`。
退出码：全部物理硬检查通过为 `0`，物理失败或摆放预算耗尽为 `2`，输入、预处理、加载、
采集或媒体错误为 `1`。未到达的阶段不生成伪造轨迹或终态。

可选 `--asset-metadata metadata.json` 按已绑定 `object_id` 提供元数据。例如：

```json
{"custom_1": {"unit_scale": 1.0, "natural_up": [0, 0, 1], "tip_limit_deg": 15}}
```

未知类别必须提供可信单位、原生自然朝向与独立倾倒规则。首版只接受原生 +Z 自然朝向，
不支持 `inside`、关节、机器人、图像或显式数值距离；当前关系的左右前后、远近阈值
继承 `scene_layout.py`。物体描述中的高度/直径尺寸单独处理。

## 资产与坐标

`repair_assets.py` 在固定版本 Genesis 中测量原生几何。MJCF 的透明碰撞显示部件
不得成为视觉正确性的参考；按原始材质透明度筛选后，单独检查可见网格。
规范坐标原点取可见包围盒 XY 中心及最低 Z。缩放为等比例，米制；明确文本尺寸、
可信单位元数据与类别先验发生冲突时拒绝。苹果最大边长 0.04–0.12 m、杯高
0.06–0.25 m、碗水平直径 0.08–0.40 m、桌高 0.50–1.20 m；无可信尺度且超出区间时
目标依次为 0.07、0.12、0.20、0.75 m。这些是项目工程先验。

原生碰撞优先。固定桌子的实测三角网格可以保持非凸；动态物体要求闭合凸部件。
不合格时按连通部件做 CoACD（1.0.14、seed 0；完整参数保存于资产报告）。legacy
的凸包/Box 后备也必须通过近似核验；新入口使用下述已登记的版本化候选。
检查包括外部代理表面误差、视觉覆盖、实测支撑面的
射线高度与空腔/桌腿间隙；不把分解内部切面当作外部支撑。派生网格采用严格双向表面
误差上限 `min(2 mm, 1%×d)`；原生碰撞允许小部分视觉装饰未参与碰撞，但要求
按面积均匀抽样的覆盖率至少 99%、底部误差不超过 1 mm，外部与支撑面检查保持。
所有最大误差均记录，资格检查失败即拒绝。有限采样的近似检查不能作为精确几何证明。

legacy 保留每个部件独立进程、120 秒限时、最多 2000 面简化的旧路径；其闭合且
绕序一致的输入关闭 CoACD 体素预处理，其他使用 auto。原 `collision_repair_v2` 使用下列固定顺序，表中
每项依次为「简化目标面数 / 整资产凸部件上限 / threshold / resolution」，原面数
表示不做简化，已低于目标面数的输入也不再简化：

| 类别 | 候选 1 | 候选 2 | 候选 3 | 候选 4 |
| --- | --- | --- | --- | --- |
| 苹果 | 8000 / 64 / 0.005 / 2000 | 20000 / 64 / 0.005 / 2000 | 原面数 / 64 / 0.005 / 2000 | 原面数 / 128 / 0.0025 / 4000 |
| 碗 | 原面数 / 64 / 0.005 / 2000 | 原面数 / 128 / 0.005 / 2000 | 原面数 / 128 / 0.0025 / 2000 | 原面数 / 128 / 0.0025 / 4000 |
| 其他 | 2000 / 64 / 0.005 / 2000 | 8000 / 64 / 0.005 / 2000 | 原面数 / 128 / 0.005 / 2000 | 原面数 / 128 / 0.0025 / 4000 |

原生碰撞仍优先；其他类别存在已合格 legacy 派生缓存时，四候选前先尝试保留其精确
碰撞网格，但须重跑 v2 完整质量检查。苹果和碗不走这个旧缓存入口。
每个资产从原生几何测量到碰撞资格完成共用 **1200 秒**预算，原生资格、缓存复核与
后续候选消耗同一份剩余时间。每次原生资格或候选都由独立进程执行，单次限时为
`min(300 秒, 剩余预算)`，候选的所有连通部件、简化与完整质量检查共用该时限；
最多 12 个非零体积组件、8 GiB 进程地址空间；CoACD 固定 OpenMP 8 线程，
OpenBLAS/MKL 固定 1 线程，线程配置与缓存绑定。缓存发布锁只等待剩余预算。共享 Genesis 初始化和
`scene.build()` 位于每资产计时之前；父进程测量、哈希和缓存锁不做抢占终止，超时
结果在后置检查中拒绝，因此 20 分钟不是整个 `prepare()` 调用的硬返回保证。

v2 只接受闭合、无边界边/非流形边、无退化/重复面、绕序一致且正体积的 CoACD
输入，关闭体素预处理。苹果简化后仅允许删除**相同三个顶点、精确反绕序**的一对
重合三角面，保留原始与清理后网格、面索引、哈希、体积核对和表面偏差记录；不删除
同向重复面，也不通过补洞或任意删面使拓扑过关。清理后仍必须通过完整拓扑门。
零体积共面装饰片不单独生成刚体碰撞。最终代理始终对完整原始可见网格执行旧质量门，
并额外要求所有 v2 代理的底部绝对误差 ≤1 mm；简化/清理网格不能替代质量参考。
初始底部偏移同时覆盖可见与碰撞最低点。原碗四候选不能满足空腔/表面几何门，
失败记录保留，扩展策略见下文。

实测支撑面高度与碰撞高度误差不超过 1 mm。支撑区域沿用完整凸覆盖证明，拒绝孔洞、
断裂及上方遮挡；终末验收始终使用完整源投影。缓存以原始几何、CoACD 参数和版本绑定，
读取验证内容哈希，写入加互斥锁。v2 成功缓存还绑定原始视觉网格、实测支撑面、
候选/拓扑/质量版本、依赖及实现哈希；内容键同时包含实际处理输入和输出碰撞部件
的哈希。命中后仍在受限进程中重跑完整质量门，失败候选只留在任务诊断目录。

原始 MJCF 的质量按 s³、惯量按 s⁵ 缩放；重新生成碰撞时继承原质量、质心、惯量及
接触参数。v2 对所有资产在候选修复前冻结原生加载的质量、质心及惯量，包括苹果与
其他网格；碰撞变化不触发新的质量估算。legacy 无质量数据的网格仍采用
600 kg/m³ 密度假设及 d/128 的碰撞并集体素估计，明确记录估计来源。
所有源文件、派生文件、初态与最终实际物理参数保留摘要绑定。
运行时把动态物体实际质量、质心和惯量重新变换到规范坐标后与冻结数据核对。
碰撞顶点按完整集合核对，避免 float32 旋转改变近共面凸包顶点成员造成误报。

## 获准扩展的碰撞生成策略

原固定候选耗尽后，用户明确允许调整生成策略，同时保持全部验收门槛。
`text_scene_v2` 现在选择独立 `collision_repair_v3` 缓存与实现版本；旧输入冻结的
策略及旧缓存仍保留，不能回写成新策略。桌子与杯子优先复用原合格几何。

- 苹果每个候选独立从原视觉网格生成：8000 面清理输入，依次尝试 256、512 部件；
  threshold=0.01、resolution=2000、MCTS iterations=5/nodes=20/max_depth=3、
  seed=0、关闭体素预处理。这些是生成参数，最终误差仍须 ≤min(2 mm,0.01d)。
- 碗从原网格实测旋转剖面，再将剖面实体分成闭合凸区域，沿原角度采样分区；
  候选最大角度索引跨度依次为 4、3，对此原资产生成 304、418 个凸部件。
  保留原外壁和内壁，完整原网格仍是双向误差、底部、空腔门的唯一参考。
- 每次 CoACD 在独立子进程中硬限时 300 秒；简化、分解、序列化、完整几何复核
  和缓存发布共享每资产剩余 1200 秒预算。外层进程超时终止整个子进程组。
  这修正了原 v2 把生成与耗时几何复核一并限制为 300 秒的问题。
- 几何检查读取实际序列化的 OBJ，复核前后绑定每个部件哈希；父进程和缓存发布
  再核验，禁止在检查后重新为改变的代理签名。命中仍重跑完整几何资格门。

碗 304 部件的独立实验及首次正式资产准备均已通过。首次完整构建的苹果在
内部切面包含性复核时触发 8 GiB 内存上限，实际物理零步；具体日志见验收记录。

## SimFoundry 物理实现对照

2026-09-07 只读检查本地 `external/SimFoundry`，重点是
`12_stabilize_physics.py`、`light_editor/settle.py` 与 `asset_conversion_utils.py`。
前者以 PyBullet 辅助摆放：每步清零线/角速度，以相邻步位移 0.1 mm、角差 0.001 rad
判断收敛，逐物体路径还临时固定已放物体，全部释放后仍清零 50 步。
编辑器则运行 OmniGibson，并以始末根位置变化 ≤5 mm 和关节位移判断是否允许发布。
这两种结论都不等价于本入口的三秒自由动态轨迹、最后一秒 ≥95% 速度/正确支撑比例。
因此不移植每步清零或终点位移作为通过依据。

可借鉴的处理已在文本入口逐项核对：碰撞地面真实加载；质量、质心、惯量及坐标变换
使用原生加载值；参数落到参与接触的几何体；源资产只读，派生结果独立保存、通过后发布。
SimFoundry 的 CoACD 子进程隔离也适用于这里，但其失败/体积比接近时使用整体凸包的
兜底不满足本轮空腔、桌腿间隙及完整视觉细节门，不能作为免检通过路径。
本次是源码对照，没有运行 SimFoundry 的 PyBullet/OmniGibson 验收，也没有修改该仓库。

## 布局与修复

`repair_geometry.py` 保留明确支撑父对象，校验单父、无环；缺少支撑时根据类别和
可容纳的实测支撑面推断，无法推断则落到地面。逐层放置，同层按尺寸降序。
每个对象每轮 50 个 yaw 候选，保持自然 roll/pitch；每个 yaw 都重新收缩支撑区域。

- 验收余量 `m=max(0.01, 0.02d)`；legacy 初始额外缓冲 `b=max(0.002, 0.005d)`，
  v2 为 `b=max(0.005, 0.005d)`，由实际资产准备路径写入布局使用的资产信息。
- 完整投影、遮挡、凸部件相交、场景边界及文本硬关系先门控。
- 固定非凸网格冻结真实三角连接，使用三角面与凸体内部裁剪及完全包含检查；不以整桌
  凸包作为精确碰撞。两个非凸固定物体的包围范围相交时，当前窄相检测返回不支持错误。
- 文本软区域指向可行域内部三分之一区域；按文本偏好、间距和边缘评分，Top-5 中按种子选择。
- 每个对象的种子来自总种子、对象 ID、重试编号；全部候选与拒绝原因写入文件。

每次试验重新加载整个场景。首个失败动态对象按支撑拓扑选择，重新采样 XY/yaw，
其支撑子树同步做刚体变换。其他对象保留上一轮候选初态；全体重新仿真、重新判定。
每对象最多 10 轮重新采样，全场景物理试验最多 `1+10×动态对象数`。第 5 次重采样起
可取消软区域偏好，物理边界和文本硬关系始终保留。输入、资产、加载、采集错误立即中止。

## 物理判定

Genesis 固定 `0e74bf392781884ccad765c3f344419c86b872ca`，CPU/seed 0；legacy dt=0.002 s，
1500 步，重力 (0,0,-9.81)，substeps=1，Newton 50、tolerance=1e-8、关闭休眠；
pyramidal/convex、impratio=1，默认 timeconst 请求 0.01 s，保留原始资产参数并记录实际值。
视觉初态先在无相机、零步进的原生加载探测中检查 1e-5 m 误差，然后才正式仿真。

2 ms 时初态加每步共 1501 行，最后 `2<t≤3` 的 500 行判定；1 ms 半步复验共
3001 行，终末窗口 1000 行。速度统一在质心计算；
`max(||v_COM||, d/2×||ω||)<0.01 m/s` 的比例至少 95%；从直接父对象得到向上力
`>1e-6 N` 的比例至少 95%。初态和全程穿透同时满足 ≤1 mm 和 <1%×较小对象 d。
终末每行检查完整投影与余量、父支撑面偏斜 ≤0.5°、当前四类自身倾倒 ≤15°、
明确空间关系和图外接触。落地后静止会因错误支撑失败。归一化位移与转角是质量分数，
1%/3° 为评分参考，不单独拒绝。任何必需对象硬检查失败都不能进入 04。

`repair_physics.evaluate` 是离线判定器，不启动 Genesis。正式采集在每一步验证连续、
有限字段、接触有效项及双方力方向，并与 link 净接触力交叉核验；磁盘轨迹独立复判。
初态未求解接触力必须为 null；异常停止并保留最后完整采样。

## 产物与视频

- `01_obj`：原文、原资产绑定及来源，复制后核验。
- `02_scene`：源快照、资产信息、派生碰撞、候选记录、支撑图与 `scene_v0.json`。
- `03_physics/attempts/000...`：每次冻结输入、实际参数、初态、连续轨迹、终态、判定、清单和视频。
- `03_physics/attempts.json`、`repair_log.json`、`physics_result.json`：全部尝试、修复与总状态。
- `03_physics/validated_scene.json`：仅通过时生成，绑定最后通过尝试的输入和轨迹。
- `04_final_render/render`：仅全部物理通过且指定 `--render` 时生成终态图片和环绕 MP4。

验证视频重放全部连续采样，960×720、50 FPS；2 ms 为 1501 帧/30.02 秒、10 倍
慢放，1 ms 为 3001 帧/60.02 秒、20 倍慢放。每个原始 PNG 都保留在 `frames/`，
`frames.jsonl` 保存逐帧路径与哈希，不抽帧凑固定时长。重放禁止物理步进，每帧
强制刷新可视缓存。编码前后分别记录互异帧数、解码帧数和时长。
最终环绕 180 帧/6 秒，仅相机运动，不能当作物理证据。视频直接绑定对应尝试的输入
与轨迹哈希，渲染错误保留诊断。帧数、互异帧和视觉变换误差见各 `render_report.json`。

构建与半步工具在媒体开始前冻结已经复判的输入、轨迹、判定、实际加载报告及相关
物理文件哈希，在验证视频、终态渲染及最终封装前检查，并从磁盘独立复判。
媒体期间修改轨迹、通过判定或加载报告不能通过重新计算清单变成有效证据。
完整性失败标为无效/执行错误，04 和已写的 `validated_scene.json` 移入 03 诊断目录，
04 保持空；原输入、失败轨迹与具体错误继续保留。

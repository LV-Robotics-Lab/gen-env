# 已有资产场景的 Genesis 物理验证实施方案

日期：2026-09-06  
状态：独立物理入口已实现；原四资产场景未通过物理门控。本文保留初始设计，实际行为、用户确认的限制和实测结果见 [README](README.md) 与 [真实验收记录](PHYSICS_VALIDATION_EVIDENCE.md)。

## 1. 目标与交付范围

把已经完成的 `02_scene` 初始布局接入真实 Genesis 刚体仿真，回答三个问题：物体能否稳定下来、是否由场景图声明的对象支撑、是否出现不可接受的穿透或关系破坏。

首个验收对象为已有任务：

```text
output/桌上放着一个苹果、一个黄色杯子和一个橙色塑料碗。/
```

复用选中的桌子、苹果、杯子和碗，以及已经求出的初始布局。本阶段不重新调用 LLM，不重新检索资产，不重新规划布局，不通过缩放或替换资产使失败场景通过。

本轮先交付独立的 `03_physics` 入口、完整物理轨迹和机读验证报告。`04_final_render` 保持 `not_run`；终态渲染后续单独接入。支持既有 `on` 和左右前后/远近关系；`inside`、内腔测量、机器人和关节任务继续延后。

## 2. 当前基础与需要补齐的内容

| 部分 | 已有能力 | 本轮需要补齐 |
| --- | --- | --- |
| 初始场景 | 已有资产绑定、原始请求、v2 场景图、布局及实测视觉支撑面 | 生成与这些输入哈希绑定的物理任务描述 |
| 物理运行 | `validate_physics.py` 已有步进、轨迹采集及稳定性/接触判定 | 支持当前任务的原生 MJCF、GLB 和内置地面 |
| 资产加载 | Genesis 官方支持 `MJCF`、`Mesh`、`URDF` | 开启并核验碰撞、自由度、质量/惯量、摩擦和坐标一致性 |
| 验收与产物 | 已有 `TaskOutput` 阶段锁、输入快照与文件清单 | 只运行物理时的阶段状态、失败报告和终态记录 |

旧验证器要求 `compile_manifest.json`，并只接受 Box、单 link URDF；这是旧平台入口的约束，**不是 Genesis 的原生限制**。新入口直接读取当前任务目录，不要求先把全部资产转成 URDF，也不要求绕经 OpenXSim 编译包。

旧入口仍保留。可提取复用其轨迹检查与数值计算，但不能直接套用它的固定 Box 桌面、包格式和物理通过后自动渲染的控制流。

## 3. 拟采用的数据流与入口

```text
01_obj 的已选资产 + 02_scene 的图、布局和实测几何
  → 核验任务清单、资产绑定、源文件及图/布局摘要
  → 生成 physics_input.json，固定本次设置、物体角色与验收条件
  → 原生加载资产，核验实际几何和物理参数
  → 初态检查
  → Genesis 真实物理步进，逐步保存轨迹与接触
  → 终末窗口稳定性、支撑及关系检查
  → 03_physics 报告与终态记录
```

拟新增入口 `validate_asset_scene.py`。入口现已实现；建议显式增加 `--fixed-object table_1 --profile baseline`。初始接口设计如下：

```bash
.venv/bin/python self_improving/sim_adapters/genesis/validate_asset_scene.py \
  --scene-dir 'output/桌上放着一个苹果、一个黄色杯子和一个橙色塑料碗。' \
  --clip-index assets/genesis/clip_non_robot_v1/index.json
```

首次接入保持独立执行，不改变现有提取/构建命令默认停在 `02_scene` 的行为。新入口成功仅代表物理阶段通过，不表示终态渲染完成。建议物理通过退出 0，运行或校验失败退出非零。

`physics_input.json` 至少包含：原始请求及上游摘要、资产绑定与源文件哈希、场景图和布局摘要、初始位姿、固定/动态角色、重力与求解参数、碰撞处理选项、明确支撑目标和其他硬关系。LLM 的软偏好不提升为物理验收硬条件。

## 4. 原生资产加载与物理准备

### 4.1 首个任务的物体角色

| 对象 | 原始格式 | 拟采用加载方式 | 首版角色 |
| --- | --- | --- | --- |
| 内置地面 | Genesis Plane | `gs.morphs.Plane` | 固定，开启碰撞 |
| table_1 | GLB | `gs.morphs.Mesh` | 固定，使用已选真实桌子 |
| apple_1 | MJCF XML | `gs.morphs.MJCF` | 动态 |
| cup_1 | MJCF XML | `gs.morphs.MJCF` | 动态 |
| bowl_1 | GLB | `gs.morphs.Mesh` | 动态 |

不额外创建替代桌面的 Box。桌子固定表示本次验证以固定桌面为环境条件，不宣称已经验证桌子自身会稳定站立。其他场景的固定对象需在运行前明确声明；不能自动固定全部支撑对象来保证堆叠通过。无明确支撑的动态根对象以地面为预期支撑，并标注这是运行环境规则。

### 4.2 碰撞与材料

- MJCF 优先保留原始碰撞部件、质量、惯量和材料参数；核验加载后的碰撞数和自由度。若要求动态的资产实际没有自由度，明确失败，不用固定悬空的结果冒充稳定。
- GLB 优先试用官方原生非凸碰撞路径，保留原始比例和朝向。官方橙色塑料碗测试可作为碰撞配置参考，不能照搬其旋转和堆叠初始位置。
- 核验物理碰撞几何与原始视觉模型的对应关系。碰撞近似、网格修复或分解必须记录处理选项、源摘要及实际结果；不得默默填平容器或以大盒子替代原模型。
- 对 GLB 缺少的质量/摩擦信息，首版使用固定 Genesis 版本的 Rigid 材料默认值作为仿真假设；运行前将具体数值和来源写入输入/加载报告。不得声称这些是实物测量值。
- 记录每个对象实际质量、惯量、摩擦、碰撞数量与固定/动态状态。密度、质量及摩擦必须有效，加载行为与预先声明不一致时停止。

### 4.3 坐标一致性

`scene_layout.json` 中的 `translation_m` 是相对于资产原生加载状态施加的平移，不能一律当作物体包围盒中心或直接当作绝对世界位置。

物理加载需要保留原始朝向和原点语义，将同一平移应用到原生加载状态。正式步进前，核对实际视觉包围范围与第二阶段记录的世界包围范围一致，沿用初始构建的 `1e-5 m` 核验精度；同时核对朝向与比例。惯性坐标系与用户坐标系不同的资产需显式转换，不通过手调位置抵消误差。

初态必须是第二阶段的真实输出。不预沉降、不重置到稳定姿态、不人为抬高物体制造“释放成功”；若初态穿透不合格，直接记录失败。

## 5. 物理运行与采集

使用仓库固定 Genesis commit `0e74bf392781884ccad765c3f344419c86b872ca`。首次基线沿用旧物理入口的主要数值设置：

| 参数 | 首版基线 |
| --- | --- |
| 后端 | CPU |
| seed | 0 |
| 重力 | `(0, 0, -9.81) m/s²` |
| 时间步 | `0.004 s` |
| 步数 | 1000，共 4 秒 |
| substeps | 1 |
| 终末检查窗口 | 最后 0.5 秒 |
| 求解器 | Newton，50 次迭代，tolerance `1e-8` |
| 休眠 | 关闭，避免把休眠当成稳定证据 |
| constraint time constant | 请求 `0.001 s`，同时记录 Genesis 实际采用值 |

正式运行不创建相机、不渲染，也不产生伪造的物理过程视频。记录初态和每一次 `scene.step()` 后的状态，正常运行共 1001 条连续记录。

每条记录包含时间、对象位置/姿态、线速度/角速度，以及真实接触对、接触点、法向、穿透深度和双方接触力。通过官方 `get_contacts()` 等接口采集，并将 geom/link 索引映射回稳定 object_id；并行接口若有 `valid_mask`，必须过滤无效项。

初态与步进后的接触语义分开：`get_contacts()` 通常对应最近一次步进结果，不能把未步进的空返回解释为“初始无碰撞”。初态使用 `detect_collision()` 及经过本机测试确认的穿透读取路径；初态没有求解得到的接触力时明确标记不可用，不伪造受力。

轨迹逐步写入 `trace.jsonl`。异常、中断、记录缺失和非有限数均保留诊断并停止，不把部分轨迹当作完整运行证据。

## 6. 验收规则

以下是首版基线；运行前固定在输入中，不能依据本次结果事后放宽。

**2026-09-08 修订（静止判据）**：原判据继承自旧的 Box/单链接 URDF 入口，其中含瞬时速度上限
`≤0.01 m/s`。该上限在本项目的真实工作区间（`convexify=false` 的非凸网格接触）**不可满足**：
静止物体的接触集会成步掉出检测集，掉出的那一步读到恰好一个自由落体步长
`g·dt`（baseline 0.039 m/s、half_dt 0.020 m/s），两个 profile 都高于 0.01。实测该极限环周期恒为
8 步，而物体本身 0.5 秒净漂移仅 0.16 mm。原图元标定夹具（Box-on-Box）掉接触率为 0，
因此从未暴露该问题。

故静止改由**位姿演化**判定（净漂移速率、窗口内偏移、净转速），瞬时速度与角速度保留在报告中
作为诊断项但不参与判定，掉接触率升为独立的一等判据。这不是放宽：新判据对真实失败的分辨力更强
（滚动的笔在 half_dt 下净转 48.96°/窗口，超限 48 倍），且 `settings()` 现在会在阈值不可满足时
直接报错。新增 `mesh_calibration` 正向对照用真实非凸网格资产守住这一区间。

| 检查项 | 通过条件 |
| --- | --- |
| 输入与资产完整性 | 上游快照、实际加载文件、图和布局摘要一致，运行后重新核验 |
| 动态物体确实参与物理 | 具有有效自由度，碰撞开启，未用固定姿态绕过验证 |
| 稳定性 | 终末窗口内相对终态最大位移 ≤1 mm、旋转变化 ≤0.5°，且净漂移速率 ≤2 mm/s、窗口内相对均值最大偏移 ≤1 mm、净转速 ≤1°/s |
| 接触连续性 | 终末窗口内该物体接触集为空的步数占比 ≤0.25 |
| 支撑接触 | 终末窗口内，声明支撑目标对源对象提供向上合力的步数比例 ≥0.8 |
| 穿透 | 初态和全程可验证接触的最大穿透 ≤1 mm；初态数据不可验证时不得通过 |
**2026-09-08 修订（支撑面与沉降判定）**：另外两处"声明了但从不核对几何"的缺陷已修复。

1. `scene_stabilization` 每步清零速度，自由落体因此每步只蠕变 `½·g·dt² = 0.0785 mm`，而收敛阈值是
   `0.1 mm` —— **悬空物体被判为已沉降**。实测鼠标场景的笔全程 0 接触、每步恒定下落 0.0785 mm，
   50 步就拿到 `candidate_ready`，自由回放收到的是一个悬空 40 mm 的姿态。现改为阈值 `0.01 mm`
   （真实收敛实测 0.001 mm）并要求收敛步必须有实际接触，`discriminating()` 断言阈值必须小于蠕变。
2. `media_support.augment_scene` 把支撑面直接写成资产视觉包围盒矩形、`z_m` 硬编码 0。实测该面
   0.499 m² 中 **23.9% 下方是空气、50.4% 低于声明高度 10 mm 以上**。现改用
   `build_scene.support_surface` 实测碰撞体顶面（该场景 0.0682 m²），并由
   `scene_physics_graph.verify_support` 在物理开跑前重新测量、要求声明面被实测顶面包含。

配套：`materialize` 的缩放改用同一套严格顶面测量（原先用的 `top_extents_m` 接受顶部 10 mm 带内
任意朝上面，比真实台面大 1.38 倍，导致缩放后台面短了约 28%）；并拒绝需要放大 2.5 倍以上才能
匹配观测足迹的支撑候选。规划余量在小台面上会逐级回退到验收红线，不会低于它。

| 支撑几何 | 终末窗口内，在目标当前局部坐标系检查完整源投影仍位于已测支撑面内，并保留原有 2 cm 余量。规划侧另留 1.5 cm 沉降余量（`PLANNING_MARGIN = MARGIN + SETTLING_SLACK = 3.5 cm`），因为规划若正好落在 2 cm 红线上，任何正常沉降位移都会越线；实测苹果沉降位移 2.8 mm，`margin_slack` 回归用例在红线外仍剩 3.28 cm |
| 明确相对关系 | 左右前后、near/far_from 使用第二阶段同一坐标约定和距离定义，在终末窗口重新验证 |
| 掉落与无效状态 | 不低于有效地面，不丢失对象；NaN/Inf、异常速度读取或接触缺失不能通过 |

“是否仍满足原文关系”和“是否静止”必须分别记录。一个苹果从桌上掉到地面后静止，仍然应当失败；只看到终态不动不能证明支撑正确。

多层支撑需要处理双向接触：中间物体可以同时接触其父支撑和它承载的子物体。完整支撑图中的直接父子接触属于声明接触；不能把子物体向下施加的载荷误判为“意外支撑”。每个动态对象的自身支撑仍须由其声明父对象提供，未声明接触单独判定并报告。

对目标局部支撑面的检查必须使用目标运行时姿态。不得退回到外层 AABB 重叠，也不得把初始视觉支撑面检查当作运行时接触证明。若父对象姿态变化超出首版支撑模型可验证的范围，应报告未支持/失败，而不是猜测通过。

## 7. 输出、状态与重跑

建议产物结构：

```text
03_physics/
├── scene_input_manifest.json    # 01/02 输入快照
├── physics_input.json           # 本次物理设置、角色与验收条件
├── asset_physics_report.json    # 实际加载几何、材料、自由度和碰撞信息
├── initial_state.json           # 原样输入的初态与初态检查
├── trace.jsonl                  # 连续真实步进记录
├── final_state.json             # 最后一条完整采样，单独标注是否通过
└── physics_result.json          # 总结果、逐项检查、失败原因和摘要绑定
04_final_render/                 # 本轮仍为空，not_run
```

新入口在任务锁内核验已完成的 `02_scene`，保留 `01_obj`、`02_scene`，只替换 `03_physics` 并清除旧 `04_final_render`。扩展 `TaskOutput` 支持“物理通过、渲染未运行”的独立完成状态；不得沿用必须渲染成功才整体成功的旧控制流。

建议总状态增加 `physics_passed` / `physics_failed`，阶段记录分别保持 objects、scene 为 passed，physics 为 passed/failed，final_render 为 not_run。配置不受支持或未开始仿真时，额外记录 `simulation_executed=false`；实际仿真后失败则记录 true，避免混淆“没有运行”和“运行没通过”。

报告绑定输入快照、资产文件、物理设置、轨迹和终态摘要。完整性失败、物理失败和采集错误均不得输出成功标记；失败产生的旧图片或旧报告不能残留为本轮成功证据。

## 8. 实施顺序

1. **定义输入与状态契约。** 新入口从已完成的第二阶段构造物理输入，校验哈希和明确关系；补充独立物理阶段的生命周期。
2. **完成四资产原生加载探测。** 逐对象核验碰撞、自由度、材料及初始位姿一致性。探测结果以独立报告保存，不提前宣称整个场景通过。
3. **接通步进采集。** 用固定桌子、动态苹果/杯子/碗运行，保存初态与每一步真实记录；失败保留原始证据。
4. **接入纯数据判定器。** 复用旧稳定性计算，扩展真实桌子/地面、目标局部支撑面和多层父子接触判定。
5. **完成回归与真实验收。** 正常场景和攻击案例同时通过后，记录已验证范围、参数与剩余限制，再考虑自动串联物理阶段和终态渲染。

新增代码放在 Genesis 平台适配器中，不修改稳定 `scene_gen` 契约，也不复制或改写官方 Genesis 引擎代码。

## 9. 测试与完成标准

### 离线测试

覆盖输入/源文件篡改、错误位姿转换、缺少动态自由度、关闭碰撞、错误支撑目标、缺失轨迹、非有限数、穿透超限、终态仍运动，以及掉到地面后静止的误报。

多层场景专门覆盖“中间物体接触父支撑与子物体是合法的”和“意外接触其他支撑对象必须失败”。复用现有支撑面有孔、断裂、遮挡和完整投影越界案例。

生命周期覆盖重跑保留 01/02、清除旧 03/04、失败不冒充通过、物理成功而终态渲染仍 not_run。旧 `validate_physics.py` 的离线回归必须保持通过。

### 真实 Genesis 验收

- 当前四资产场景至少重复运行 3 次，保留每次轨迹和判定结果；任何失败都如实记录。
- 再以 `dt=0.002 s`、2000 步运行相同 4 秒场景，检查关键结论对时间步变化的敏感性；不能通过缩短物理时长获得通过。
- 验证一个具有实测支撑面的多层场景，例如桌子→微波炉→苹果；中间可承载对象保持动态，才能验证堆叠本身。
- 攻击场景包含初始深穿透、固定悬空、关闭碰撞、落到错误目标和终末仍运动。固定悬空与关闭碰撞应在输入/加载门控拒绝，其他适用案例需要实际运行。
- 核验物理运行期间没有渲染，轨迹连续、哈希完整，所有动态对象参与实际仿真。若某资产失败，先诊断其碰撞和材料等原因，不能放宽阈值或替换资产后仍称原场景通过。

完成时运行仓库 `pytest -q`、Genesis 离线测试、相关 lint/CLI 检查，并更新 README、中文平台指南和真实验收记录。这里只执行 Genesis 平台适配；不将结果等同于 RoboTwin/SAPIEN 或 OpenXSim 高层任务验收。
